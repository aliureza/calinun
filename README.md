# کالینون 🍽️

وب‌اپ (PWA) برای دیدن رزروهای غذای سامانهٔ کالینان؛ نصب‌شدنی، ریسپانسیو، با یادآوری پیش از هر وعده.

## چطور کار می‌کند

سایت کالینان API ندارد و ورودش با کپچا و کوکی است؛ پس مرورگرِ یک اپ ایستا نمی‌تواند مستقیم به آن وصل شود (CORS و کوکی‌ها). راه‌حل: یک **سرور کوچک** که نشست کالینان را نگه می‌دارد.

```
گوشی (PWA روی GitHub Pages) ──HTTPS+توکن──▶ سرور کالینون ──نشست کالینان──▶ سایت کالینان
        ▲                                         │ هر ۲۰ دقیقه صفحهٔ رزرو (۴ هفته) را می‌خواند
        └──────────── Web Push ◀──────────────────┘ و پیش از وعده نوتیف می‌فرستد
```

**ورود فقط یک‌بار:** کاربر آدرس صفحهٔ ورود را می‌دهد ← صفحهٔ ورود کالینان از طریق سرور باز می‌شود (با نوار «ورود امن از طریق کالینون») ← بعد از ورود موفق، سرور نشست را رمزنگاری و ذخیره می‌کند و کاربر را با یک کد یک‌بارمصرف به اپ برمی‌گرداند ← از آن به بعد اپ نشان داده می‌شود.
**دکمهٔ شناور «سایت کالینان»:** همان نشستِ ذخیره‌شده را در یک تب جدید باز می‌کند، پس برای کارهای دیگر دوباره لازم نیست وارد شوی.

## ۱) دمو روی GitHub Actions (بدون سرور)

۱. این پوشه را در یک مخزن GitHub بگذار (شاخهٔ `main`).
۲. **Settings → Pages → Source: GitHub Actions**.
۳. Push کن؛ ورک‌فلو `Build & deploy PWA` تست‌ها را اجرا و سایت را منتشر می‌کند.
۴. آدرس `https://USER.github.io/REPO/` را روی گوشی باز کن → «ورود به نسخهٔ دمو» → از منوی مرورگر «Install / افزودن به صفحهٔ اصلی».
   در دمو همهٔ صفحه‌ها با داده‌های نمونه کار می‌کنند و در **تنظیمات ← آزمایش نوتیف** می‌توانی ظاهر نوتیف را ببینی.

## ۲) اتصال واقعی

**سرور** (Node ≥ 20، بدون هیچ وابستگی npm):

```bash
cd server
npm run keys              # MASTER_KEY و کلیدهای VAPID را می‌سازد
cp .env.example .env      # PUBLIC_URL، APP_URL، ALLOWED_HOSTS و کلیدها را پر کن
npm start
```

یا با Docker: ورک‌فلو `Build server image` ایمیج را در GHCR می‌سازد (`docker run --env-file .env -v data:/data -p 8787:8787 …`).
حتماً پشت HTTPS (Caddy / nginx / Cloudflare) منتشر کن و `TRUST_PROXY=true` بگذار.

**اپ:** در مخزن: *Settings → Secrets and variables → Actions → Variables* مقدار `API_URL` را برابر آدرس https سرور بگذار و ورک‌فلو را دوباره اجرا کن.

نکتهٔ مهم: `PUBLIC_URL` (سرور) و `APP_URL` (اپ) باید **دو origin متفاوت** باشند؛ سرور از پیکربندی هم‌مبدأ جلوگیری می‌کند.

## امنیت

- **رمز عبور ذخیره نمی‌شود.** فقط نشست (کوکی) ذخیره می‌شود؛ تست خودکار هم تأیید می‌کند چیزی از آن روی دیسک خوانا نیست.
- ذخیره‌سازی روی دیسک با **AES‑256‑GCM** رمزنگاری و ضدِ دست‌کاری است؛ فایل با دسترسی `0600`.
- توکن اپ تصادفی ۲۵۶ بیتی است؛ سرور فقط **هش SHA‑256** آن را نگه می‌دارد. کد بازگشت از ورود **یک‌بارمصرف و ۲ دقیقه‌ای** است و هرگز در تاریخچهٔ مرورگر نمی‌ماند.
- **ضد SSRF:** فقط هاست‌های `ALLOWED_HOSTS`؛ فقط https؛ فقط پورت ۸۰/۴۴۳؛ آدرس‌های داخلی/loopback/link‑local حتی بعد از DNS مسدود می‌شوند (جلوگیری از DNS‑rebinding).
- نشانیِ اشتراک نوتیف فقط به سرویس‌های واقعی Push (FCM، Mozilla، Apple، Windows) مجاز است.
- کوکی‌های کالینان **هرگز به مرورگر نمی‌رسند**؛ پروکسی ورود با COOP و `no-referrer` ارائه می‌شود و لینک آن بعد از ورود یا ۱۵ دقیقه می‌میرد.
- **فقط‌خواندنی:** تنها POSTهای سرور به کالینان، سه دکمهٔ تغییر هفته است؛ هیچ رزرو/لغوی انجام نمی‌شود.
- CSP سخت‌گیرانه (بدون inline script/style)، escape همهٔ داده‌های سرور در UI، CORS فقط برای origin اپ، محدودیت نرخ، حداکثر کاربر، و حذف خودکار حساب‌های رهاشده (`INACTIVE_DAYS`).
- پیام «خروج و حذف اطلاعات» نشست و همهٔ داده‌ها را از سرور و دستگاه پاک می‌کند.
- **وابستگی صفر** در سرور (Web Push و رمزنگاری با `node:crypto`) → سطح حملهٔ زنجیرهٔ تأمین ناچیز.

## محدودیت‌ها و ریسک‌ها (صادقانه)

- **این برنامه را فقط روی سایتی استفاده کن که اجازه‌اش را داری** و فشار اضافه نیاور (۴ هفته ≈ ۶ درخواست در هر ۲۰ دقیقه برای هر کاربر).
- **شبکه:** اگر سایت کالینان فقط از داخل ایران/شبکهٔ دانشگاه در دسترس است، سرور هم باید همان‌جا (VPS داخلی یا داخل دانشگاه) باشد؛ برای شبکهٔ خصوصی `ALLOW_PRIVATE_UPSTREAM=true`. توجه: ارسال Web Push به FCM/Apple از سرور داخل ایران ممکن است فیلتر باشد — در این صورت نوتیف نمی‌آید ولی بقیهٔ برنامه کار می‌کند.
- **پروکسی ورود به سایتِ واقعی تست نشده است** (من فقط به فایل HTML شما و یک سایت شبیه‌سازی‌شده دسترسی داشتم). اگر ورود با کپچا یا اسکریپت‌های خاص خراب شد، `GET /p/...` را در لاگ بررسی کنید؛ ممکن است قوانین بازنویسی در `server/src/proxy.js` نیاز به اصلاح داشته باشد.
- مسیر صفحهٔ رزرو به‌صورت پیش‌فرض `/Reservation/Reservation.aspx` است (از روی منوی فایل شما)؛ در صورت تفاوت، در «تنظیمات پیشرفته»ِ ورود یا با `RESERVATION_PATH` تغییر بده.
- ساعت وعده‌ها در HTML نبود؛ پیش‌فرض‌ها (ناهار ۱۲–۱۴:۳۰، شام ۱۸–۲۰:۳۰) در تنظیمات قابل تغییر است.
- اگر کالینان نشست را منقضی کند، اپ بنر «ورود دوباره» نشان می‌دهد و (در صورت فعال‌بودن نوتیف) خبر می‌دهد.
- در آیفون، نوتیف فقط وقتی کار می‌کند که برنامه به «صفحهٔ اصلی» اضافه شده باشد (iOS ≥ 16.4).
- ورود/خروج در تب پروکسی‌شده (دکمهٔ «سایت کالینان») نشست مشترک را تغییر می‌دهد؛ اگر در آن‌جا «خروج» بزنی، باید دوباره وارد شوی.

## ساختار

```
web/        اپ (HTML/CSS/JS ساده، بدون build)   ← روی GitHub Pages
server/     سرور بدون وابستگی (API، پروکسی ورود، جمع‌آوری، Push)
scripts/    build-web.mjs  (می‌سازد: dist/، تنظیم API_URL، نسخهٔ cache)
.github/    pages.yml (تست + انتشار) · server-image.yml (ایمیج Docker)
```

تست‌ها: `npm test` — ۲۹ تست سرور (پارسر روی صفحهٔ واقعی ناشناس‌شده، رمزنگاری Push، پروکسی، ورود، انقضای نشست، امنیت) و ۳ تست دود برای رابط.

فونت: ورک‌فلو فونت وزیرمتن (OFL) را در زمان build می‌گیرد؛ اگر نشد، فونت سیستم استفاده می‌شود.
